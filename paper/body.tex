\section{Introduction}

A practical memory contract should answer four questions: what output stays
unchanged, what fresh computation serves as the reference, which numerical
implementation is used, and whether the claim survives later updates. A cache
can shrink without answering them, and a fact can stop being recalled while its
influence remains in state. Dense caches and recurrent memories can be
effective, but dense state alone does not ordinarily identify entries known to
contribute zero or specify what state a deletion should reproduce.

Support Vector Attention (SV-Attention) makes those statements possible by
fitting a one-class boundary---estimated from the context keys alone, without
negative examples---around the key vectors~\citep{ocsvm,svdd}. Each
key receives a nonnegative coefficient that is used directly in the readout.
Positive-coefficient keys are \emph{active} and form the support set; exactly
zero coefficients form the reserve set. This yields two auditable contracts.
Removing a reserve key without rerunning the optimization preserves the current readout
(Proposition~\ref{prop:reserve}). Deleting an active key through the maintained
solver targets a fresh fit (refit) on the retained keys under the same per-key
coefficient cap \(C\) (Proposition~\ref{prop:decrement}).

We test completion coverage---the fraction of attempted deletion paths that
finish---and numerical agreement. Each completed trial compares
the maintained deletion with a fresh retained-key fit on retained, removed, and
perturbed keys using the gate's scalar boundary score (the \emph{gate score},
defined formally in Section~\ref{sec:gate}). Across \(1{,}200\)
fp64 trials on Gaussian keys,
clustered near-duplicates, hourly vital-sign keys from Medical
Information Mart for Intensive Care IV (MIMIC-IV), and key projections from a
trained recall model, \(1{,}199\) complete. The median of the per-trial maximum
gate-score discrepancies ranges from
\(4.5\times10^{-13}\) to
\(5.7\times10^{-7}\). On the reference CPU, the median
per-trial ratio of fresh-refit time to maintained-deletion time is
\(24\)--\(223\times\). The one uncovered margin-empty
path---a state with no coefficient strictly between \(0\) and \(C\)---remains
in the denominator.

The reserve result also has a sharp boundary. Example~\ref{ex:future} adds a
later token (an \emph{admission}) that gives an earlier reserve point positive
weight. Therefore,
pruning a reserve point now cannot certify the same future states as a run that
retains every token (Proposition~\ref{prop:not-future}). Together, the
proposition and counterexample state what the gate proves now and what a
stronger streaming guarantee would require.

Verification and training deliberately use separate numerical paths. The
verification solver uses fp64 arithmetic, updates the existing coefficient
solution, and reuses a stored matrix inverse. The
training path instead solves many coefficient problems in parallel with a
stabilized approximation. Each claim applies only to the arithmetic path that
supports it. Table~\ref{tab:contract} summarizes these boundaries.

Our contributions are:

\begin{enumerate}
\item \textbf{A two-sided characterization of reserve removal.} We prove the
point-in-time certificate and prove, by construction, that reserve status alone
does not guarantee full-history equivalence for every future admission
sequence.
\item \textbf{A measured fixed-\(C\) deletion contract.} We name the retained
refit target and report \(1{,}199/1{,}200\) numerical coverage alongside
completed-trial median, mean, and worst deviations.
\item \textbf{A verification/training separation.} The maintained path supplies
deletion updates and a custom gradient computation that reuses the stored
inverse; the batched path supplies parallel trainability. Their guarantees do
not transfer between implementations.
\item \textbf{A regime map for selection.} When every method keeps the same
number of tokens, mean recall on held-out rare-group queries is \(0.861\)
versus \(0.319\) for an oracle attention-mass proxy under skewed redundancy.
A same-channel intensive-care-unit probe, where the selector sees the vitals
used to define the event label, retains \(0.80\) versus \(0.05\) of event hours;
after the event-defining blood-oxygen saturation (SpO\(_2\)) channel is withheld
from every selector, retention is \(0.464\) versus \(0.225\). A control with the
support-vector gate disabled isolates selection, while a seven-seed
language-model result (\(p=0.001\)) establishes small-scale trainability.
\end{enumerate}

\paragraph{Scope.}
The certificates concern the solved context and a fixed-\(C\) retained-key
reference. They do not establish future-safe pruning under arbitrary
admissions or general quality and throughput superiority; downstream controls
and larger fixed-budget runs locate those open boundaries.

\section{Related Work}

\textbf{Test-time learning and recurrent memory.} These methods update a memory
state while processing tokens at inference time rather than repeatedly reading
the complete history. Linear attention,
DeltaNet, the mesa layer, Titans, and selective state-space models treat
context processing as an online learning or recurrent-memory
problem~\citep{lina,fwp,deltanet,mesa,mesanet,titans,mamba}. These methods
compress history into dense online or recurrent state; they do not ordinarily
identify a token whose coefficient is exactly zero in a declared convex
problem (one with no nonglobal local minima), nor retain the solver matrix
needed to compare deletion with solving
again on retained keys. SV-Attention contributes that audit interface: a named
reference problem, exposed coefficient groups, and a separate claim for each
operation. This is a structural distinction, independent of quality or speed.

\textbf{Cache selection.} Heavy-Hitter Oracle (H2O) and SnapKV rank stored
key--value entries using measured attention statistics~\citep{h2o,snapkv}.
Neither supplies the present output/deletion contract; retained-cache quality
is evaluated empirically. VeriCache preserves outputs by retaining a full
reference cache for verification~\citep{vericache}. SV-Attention instead
certifies that a zero-coefficient entry is inert for the current solved gate,
but it does not retain a full history and therefore does not inherit future
equivalence after later additions.

\textbf{Unlearning and differentiable optimization.} Exact machine
unlearning is commonly defined relative to retraining without the target
data~\citep{caoyang,unlearn}. Efficient Computational Optimization (ECO)
applies decremental support vector machine (SVM) machinery to a classifier
head~\citep{eco}; we apply a fixed-\(C\) decrement to context memory.
OptNet and differentiable convex layers obtain gradients from the optimality
equations of their forward optimization problems~\citep{optnet,dcl}. The
maintained Cauwenberghs--Poggio (C\&P) deletion path~\citep{cp2000} already
stores the corresponding system inverse, which its custom gradient computation
reuses.

\section{Memory contract and method}\label{sec:method}

\subsection{The fixed-\(C\) support-vector gate}\label{sec:gate}

Each token has a key \(x_i\in\mathbb{R}^d\), which acts as its memory address,
and a value \(v_i\in\mathbb{R}^{d_v}\), which carries the content mixed into
the output. A query \(q\) requests content by similarity to the keys, and
\(\alpha_i\geq0\) is the gate coefficient assigned to key \(i\). The normalized
readout is
\begin{equation}
o(q)=
\frac{\sum_i \alpha_i\kappa(q,x_i)v_i}
     {\sum_i \alpha_i\kappa(q,x_i)},\qquad
\kappa(a,b)=\exp(-\lVert a-b\rVert^2/\sigma^2).
\end{equation}
Here \(\kappa\) is a radial-basis-function (RBF) similarity: nearby vectors
receive larger values, and \(\sigma\) sets the distance scale. The coefficients
solve support vector data description (SVDD), a convex optimization problem
that fits a soft boundary around the keys:
\begin{equation}
\min_{\alpha}\;
\alpha^\top K\alpha-\operatorname{diag}(K)^\top\alpha
\quad\text{s.t.}\quad
\sum_i\alpha_i=1,\qquad 0\leq\alpha_i\leq C,
\label{eq:svdd}
\end{equation}
where \(K\) is the matrix of pairwise key similarities,
\(K_{ij}=\kappa(x_i,x_j)\). The solver hyperparameter \(C\) is the maximum
coefficient any key may receive. When we report the user-facing sparsity
parameter \(\nu\), we use it only once
to set \(C=1/(\nu n_0)\) at a declared initial size \(n_0\); deletion and refit
do not change \(C\) when the number of keys changes. Because the coefficients
must sum to one, a problem with \(n\) keys is feasible only when \(nC\geq1\).

The Karush--Kuhn--Tucker (KKT) optimality conditions divide keys according to
where their coefficient lies: the margin, or free-coefficient, set
\(S=\{i:0<\alpha_i<C\}\); the legacy ``error,'' or upper-bound, set
\(E=\{i:\alpha_i=C\}\); and the reserve, or zero-coefficient, set
\(R=\{i:\alpha_i=0\}\). Here ``error'' names a coefficient group, not a solver
failure.

For numerical state comparisons, the implementation exposes the scalar
\emph{gate score}
\begin{equation}
s(x)=2\sum_i\alpha_i\kappa(x,x_i)-\rho,
\label{eq:gate-score}
\end{equation}
where \(\rho\) is the scalar offset in the KKT system. This explicitly defined
implementation score is distinct from the normalized readout \(o(q)\).

\begin{proposition}[Point-in-time reserve certificate]\label{prop:reserve}
Let \(\alpha^\star\) solve Equation~\ref{eq:svdd} for a fixed context and fixed
\(C\). If \(\alpha^\star_j=0\), then evicting key \(j\) without re-solving
leaves the objective value and the normalized readout \(o(q)\) unchanged for
every query with nonzero denominator. The restricted coefficient vector is
also optimal for the retained-key problem.
\end{proposition}

\begin{proof}
Restricting \(\alpha^\star\) to the retained indices preserves the coefficient
sum and bounds, and every objective term involving \(j\) vanishes because
\(\alpha^\star_j=0\). Conversely, any better retained-key solution could be
extended by a zero coefficient at \(j\), contradicting optimality of
\(\alpha^\star\). The numerator and denominator of the readout likewise lose
only a zero-weight term.
\end{proof}

This exact-arithmetic statement applies to the solved state. The implementation
classifies reserve coefficients at a declared tolerance and logs the realized
readout residual separately.

\begin{proposition}[No unconditional future-equivalence guarantee from reserve
status alone]
\label{prop:not-future}
Membership in the reserve set of the current solved problem is insufficient to
guarantee equivalence between a previously pruned state and the full-history
solve after arbitrary future admissions.
\end{proposition}

\begin{proof}
Example~\ref{ex:future} is a counterexample: the same key has zero coefficient
before the admission and positive coefficient afterward, and the two gate
scores then differ.
\end{proof}

Thus a future-safe result requires additional restrictions on admissions or
geometry, or enough retained information to revisit earlier decisions.

\subsection{Active-token deletion (decrement) and refit target}\label{sec:increment}

To delete an active, positive-coefficient token, the C\&P reverse update
decreases that token's coefficient to zero while preserving the KKT conditions
and updating the stored inverse \(\mathcal{R}=M^{-1}\), where
\begin{equation}
M=
\begin{bmatrix}
0 & \mathbf{1}^\top\\
\mathbf{1} & 2K_{SS}
\end{bmatrix}.
\end{equation}
Here \(K_{SS}\) is the similarity submatrix for margin keys, and \(M\) combines
that submatrix with the coefficient-sum constraint.

\begin{proposition}[Fixed-\(C\) decrement target]\label{prop:decrement}
Assume the retained-key quadratic program (QP) in
Equation~\ref{eq:svdd} has a unique coefficient optimum. If the algebraic C\&P
reverse path completes while maintaining the KKT conditions and drives the
deleted coefficient to zero, its restricted coefficient vector equals a fresh
retained-key solution of Equation~\ref{eq:svdd} under the same \(C\).
\end{proposition}

\begin{proof}
At completion, removing the zero target coefficient leaves a retained-key state
that satisfies the original coefficient constraints, stationarity, valid
multiplier signs, and complementarity (a bound's multiplier is zero unless that
bound is tight) under the unchanged cap \(C\). These KKT conditions are
sufficient for the convex quadratic program, and uniqueness identifies the
coefficient vector with the fresh refit.
\end{proof}

When the retained KKT solution also fixes the scalar offset \(\rho\), the full
state coincides. With non-unique duplicate solutions, raw coefficients and
their margin/error/reserve assignments may differ while the gate score in
Equation~\ref{eq:gate-score} agrees. We therefore use the largest absolute
gate-score difference over a declared finite set of probes as the primary
duplicate-invariant metric and report completion coverage separately. This is
sampled numerical agreement, not equality over every possible input.

\subsection{The two numerical paths}\label{sec:method-solver}

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figs/two_numerical_paths.png}
\caption{\emph{Separate arithmetic for verification and training.}
The maintained double-precision path audits deletion against a fresh refit and
reuses a stored matrix inverse during gradient computation. The batched
approximation gives up that maintained structure to train many problems in
parallel. Each claim applies only to the path that supports it.}
\label{fig:paths}
\end{figure}

\paragraph{Maintained verification path.}
The fp64 implementation updates the stored inverse after each matrix change
affecting one key (a low-rank update) and periodically recomputes it from
scratch to control accumulated rounding error.
While no key changes coefficient group, the custom vector--Jacobian product---
the reverse-mode operation that maps output gradients to input gradients---
multiplies by \(\mathcal{R}^{\top}\); it performs no second system solve
(Appendix~\ref{app:vjp}). ``Exact'' refers to the algebraic fixed-\(C\) target.
Every implementation claim is accompanied by measured coverage and tolerance.

\paragraph{Stabilized training path.}
For each sequence, attention head, and fixed token block (chunk), the Fast
Iterative Shrinkage-Thresholding Algorithm (FISTA) performs accelerated
projected-gradient steps in fp32 and estimates the coefficient groups. PyTorch
then batches their padded KKT systems, adds a
\(10^{-3}\) diagonal ridge for numerical stability, and differentiates the
linear solve with autograd
(Appendix~\ref{app:solver}). These coefficients are an approximation to
Equation~\ref{eq:svdd}. This path is trainable, but it is not the maintained
solver, does not reuse its inverse, and supplies no deletion certificate.

The separation in Figure~\ref{fig:paths} is deliberate. Verification favors a
maintained, inspectable fp64 state; training favors batched GPU operations. A
trained model can still be audited by freezing its keys and
re-solving those keys on the maintained path.

\subsection{Causal usability probe}\label{sec:method-hybrid}

To test autoregressive use, where a query may access only earlier tokens, the
causal layer updates its long-range gate only at chunk boundaries and adds
ordinary softmax attention over recent tokens. This hybrid tests whether the memory can participate in end-to-end
training. The local softmax path has no support-vector certificate. Continued
reserve pruning preserves the readout at each pruning event, but the resulting
sequence of states is not certified equal to a run that retains every token.

\section{Fixed-\(C\) deletion verification}\label{sec:forget}

We compare decrement with a fresh retained-key refit under identical \(C\) on
four regimes: Gaussian keys, redundant near-duplicates, real hourly MIMIC-IV
vitals, and keys produced by a trained recall model. Each of the \(300\)
attempted trials per regime removes two points and evaluates retained keys,
removed keys, and retained keys perturbed by Gaussian noise of scale \(0.1\).
As a comparator, \emph{coefficient decay} leaves the target keys present,
multiplies their coefficients by \(0.01\), and does not re-solve.
Figure~\ref{fig:deletion} and Table~\ref{tab:deletion} report completion
coverage before numerical agreement.

The single uncovered trial hits the implementation's explicit
margin-set-empty path. It is classified as an edge case, not removed from the

\(52\%\), while the median of the per-trial maximum gate-score errors is

\paragraph{Deletion cost and concrete records.}
Across \(30\) uniform-random token removals at each
\(n\in\{120,256,384,512\}\), per-size median maintained-deletion latency is
\(0.30\)--\(1.04\) wall-clock milliseconds on the reference CPU. The median
per-trial ratio of fresh-refit time to maintained-deletion time is
\(24\)--\(223\times\); timing is hardware-specific. On frozen learned keys,
deleting one fact leaves the other seven facts answerable, and remove--add
corrects one learned key--value association (binding). On MIMIC-IV records, the completed
fixed-\(C\) path removes the selected patient's gate weight while retaining the
others. These are gate-score/readout audits, not a formal privacy guarantee or
deletion from model weights.

\section{Selection helps under a declared regime}\label{sec:selection}

The gate is a one-class boundary estimator, not a universal importance score.
Its selection bias is useful when informative tokens are atypical or when
context contains dense duplicates. To isolate selection, every method retains
the same number \(k\) of tokens and uses equal retained-key coefficients with
the same RBF similarity readout.

\centering
\includegraphics[width=0.94\linewidth]{figs/selection_scope_v2.png}
\caption{\emph{The selection advantage is regime-specific.}
\emph{(a)} Under skewed redundancy, support-set selection improves held-out
rare-group query recall relative to a custom H2O-style oracle that ranks keys
by their summed RBF similarity to all evaluation queries. \emph{(b)} On real
intensive-care-unit (ICU) streams, atypical
deterioration hours align with the support boundary. The threshold label shares

retention-mechanics probe rather than independent predictive evidence.}
\label{fig:selection}
\end{figure}

\paragraph{Skewed redundancy.}
Contexts contain six singleton groups and six groups of ten near-duplicates.
Every policy keeps the support set's mean \(56\%\) token count. Rare-group query
recall is the fraction of held-out queries near singleton-group centers whose
returned group is correct, averaged across trials. It is \(0.861\) for support
selection, versus \(0.319\) for the oracle above, \(0.472\) when \(k\) tokens
are sampled uniformly without replacement, and \(0\) when only the final \(k\)
tokens are retained (recency). The support-vector policy itself does not inspect
the queries. This is a fixed-context result; after later additions, the pruned
sequence is evaluated empirically rather than certified against full history.

\paragraph{Real ICU streams.}
This experiment is designed to test retention mechanics: the threshold label
shares five physiological channels with the gate's six standardized inputs.
The MIMIC-IV cohort contains \(1{,}465\) eligible stays and \(222{,}935\)
hourly tokens; the retention analysis uses the \(1{,}329\) stays containing at
least one threshold-defined deterioration hour. The six inputs are heart rate,
systolic and diastolic blood pressure, respiratory rate, blood-oxygen
saturation (SpO\(_2\)), and temperature. An event occurs when heart rate,
systolic pressure, respiratory rate, SpO\(_2\), or temperature crosses
respectively \(130/40\) beats/min, \(200/90\) mmHg, \(30/6\) breaths/min,
\(90\%\), or \(38.5/35^\circ\)C (upper/lower thresholds where applicable).
For each stay, threshold-hour retention is the
fraction of event hours whose tokens are retained; reported values average this
fraction across stays. At the support-defined mean \(33\%\) per-stay token
budget, retention is \(0.80\) for the support set versus \(0.05\) for a custom
H2O-style density proxy that keeps the \(k\) hours with greatest summed RBF
similarity to all other hours.
The magnitude is therefore mechanistically expected, not independent clinical
prediction. We therefore add a held-out-channel control: events are defined by
unstandardized hourly SpO\(_2<90\%\). Missing values are filled forward and
backward within a stay, with remaining gaps replaced by the cohort median;
SpO\(_2\) is then removed from every selector's input. Across the \(718\) stays
containing such an event, at a matched mean \(32\%\) token budget, support
selection retains \(0.464\) of event hours versus
\(0.225\) for the H2O-style selector (recency \(0.409\); random \(0.333\)).
The paired mean difference is \(0.239\). Resampling the \(718\) paired
stay-level differences with replacement \(10{,}000\) times gives a 95\%
percentile interval of \(0.194\)--\(0.284\), treating stays as independent.
This control removes direct label-channel reuse while preserving the same
selection protocol. A separate task predicts whether an event occurs within
the next six hours. SV-Attention reaches AUROC \(0.696\), below the LSTM at
\(0.783\) and softmax attention at \(0.751\). Selection that preserves atypical
hours does not by itself optimize local trend prediction.

\paragraph{\textbf{Negative control---the gate does not explain distinct-key
recall.}}
On ten-pair distinct-key recall, recall@1---the fraction of queries whose
highest-scoring retrieval is correct---is \(0.970\) for the ungated RBF readout
versus \(0.955\) with the SVDD coefficient gate. Its support fraction, the
fraction of keys with positive coefficient, is \(1.00\). Every key is therefore
active: the gate performs no token selection in this regime, which explains why
turning it off does not hurt. The useful component is the RBF readout. This
ablation prevents us from attributing clean retrieval gains to the gate. Our
positive selection evidence is confined to the evaluated redundancy and
atypicality probes in Figure~\ref{fig:selection}.

\section{Trainability and language-model usability}\label{sec:trainable}

\subsection{Gradient and solver checks}\label{sec:grad}

The maintained custom gradient matches finite differences for coefficients,
gate scores, and the complete readout. A trainable student layer reduces mean-squared error against a
fixed teacher mapping by \(99\%\) in \(200\) optimizer steps. The batched ridged
path also passes end-to-end gradient checks, but that validates the stabilized
approximation it differentiates, not the unregularized fp64 coefficients.

\subsection{Throughput boundary}\label{sec:throughput}

At the \(3.22\)M-parameter configuration, PyTorch runs the packed linear-system
solve and readout on the CPU while MLX runs FISTA on the GPU. This mixed path
reaches \(9{,}125\) tokens per timed
forward/loss/backward second on an Apple M3 Ultra, \(35.8\times\) slower than
the repository's unfused MPS softmax. The CPU softmax diagnostic is also
\(6.1\times\) faster. Maintained fp64 inference that explicitly updates the
coefficient groups is slower still.
These measurements establish that small experiments are feasible; they do not
establish a competitive architecture or accelerator kernel.

\subsection{Language modeling is a bounded probe}\label{sec:quality}

enwik8 is a byte-level English Wikipedia language-model benchmark; we use its
first \(5\) million bytes. For each run, best-validation bits per character
(BPC; lower is better) is the lowest validation loss observed during training.
At \(3.22\)M parameters, all seven paired seeds favor the hybrid. Mean BPC is
\(2.178\) versus \(2.383\) for a sliding-window Transformer whose
visible-token count matches the hybrid's measured active long-range state plus
local window. The mean paired relative improvement is \(8.6\%\), and a
two-sided paired \(t\)-test on the absolute BPC differences gives
\(p=0.001\). On TinyStories, the hybrid has lower BPC on all three seeds, a
directionally positive but non-significant result (\(p=0.057\)).

At matched \(6{,}000\)-step budgets, the larger-scale comparison reverses. At
\(10\)M parameters and five seeds, the hybrid is \(2.5\%\) worse on average
with high between-seed variation; one \(32\)M run is substantially behind.
These runs do not match models at convergence. The traces suggest slower and
less stable gate optimization, but whether the ordering persists at matched
convergence remains open. Thus the small-scale result establishes trainability,
while the larger runs identify an optimization problem rather than a
scale-level quality verdict.

\section{Discussion and limitations}\label{sec:limitations}

The central result is an operational memory contract. A constrained memory
fitted at test time exposes zero coefficients and a conditional algebraic
deletion path targeting the same-\(C\) retained-key optimum. This enables
point-in-time selection and retained-refit deletion statements that an
undifferentiated dense state does not expose. Their conditions are:

\begin{itemize}
\item \textbf{Selection is point-in-time.} Removing a current reserve token
preserves the exact solve's current readout; implementation residual is
tolerance-bounded. Future admissions can activate that token in the full-history
solve, so bounded streaming is an empirical pruned trajectory.
\item \textbf{Deletion is relative to fixed \(C\) and retained keys.} Changing
\(C\), contextualizing neighbors again, or deleting from pretrained weights
defines a different reference problem.
\item \textbf{The implementation is numerical.} \(1{,}199/1{,}200\) audited
trials complete; completed-trial deviations include a visible
\(1.1\times10^{-2}\) worst case. The margin-empty path needs a production
implementation or explicit refit fallback.
\item \textbf{Training and verification use different solvers.} The batched
path is approximate and does not inherit fp64 deletion or inverse-reuse claims.
\item \textbf{Current performance has a measured boundary.} The present path is
much slower than softmax, trails the ICU prediction baselines, and has no
confirmed language-model advantage beyond small scale.
\item \textbf{The threat model is narrow.} We measure state, gate-score, and
readout agreement, not attacks that test whether a record participated in the
stored state (membership inference), prior snapshots, or legal compliance.
\end{itemize}

These limitations change how the system should be used. A fixed-context memory
can expose an auditable current support set and a verified deletion path. A
production streaming system must either retain enough information to revisit
future active sets, accept an empirical pruning policy, or derive a stronger
future-safe certificate under additional assumptions.

\section{Conclusion}

SV-Attention turns its exposed coefficient groups into an auditable memory interface.
Reserve coefficients provide a proved point-in-time removal certificate, and a
named counterexample proves that current reserve status alone does not
guarantee full-history equivalence for every future admission sequence.
Active-token decrement has an explicit algebraic target---the fixed-\(C\)
retained-key refit---and the fp64 implementation completes
\(1{,}199/1{,}200\) audited trials with its numerical distribution reported. A
separate batched path demonstrates that the mechanism can be trained without
conflating training arithmetic with verification arithmetic. Our positive
selection evidence is confined to the evaluated redundancy and ICU
atypicality probes. Within that scope, the results give an operator a concrete
answer to what was solved, what can be removed now, and what reference state
deletion matches.
